电赛总结

赛果与遗憾

今年四川省电赛省赛结束，很遗憾没有拿奖。G 题第三题被扣了一分，就差这一分与奖项失之交臂。技不如人，接受现实，但收获不少。

方案概述

本次方案采用 FPGA + STM32F4 双模块架构，两模块之间通过 SPI 通信，是我们学校第一个采用这种方案的队伍，在实时快速通信上学到了很多。

从事后来看，有更优的解法：使用算力更强的 FPGA（我们学校没有），可以直接调用 FFT IP 核加上十一级滤波 IP 核，把奈奎斯特采样区间进一步扩大，提升精度。受限于学校硬件条件，只能用 AD9226 + FPGA + STM32F4 这套方案，虽然比较麻烦，但资源足够。

踩坑记录

AD9226 输入满量程问题

没有仔细读 AD9226 的 datasheet，不知道这颗 ADC 的输入满量程只有 ±2V（由内部参考电压决定）。当时信号幅度设计和这个范围对不上，想加一级前置放大器来处理，又因为普通运放带宽和瞬态电流驱动能力不足，无法正确驱动高速 ADC 的开关电容输入，直接失败。AD9226 的 datasheet 里有推荐的配套驱动放大器（如 AD8138 差分驱动），这就是为什么读手册很重要。

波形显示

显示波形时不要直接把采集的原始点位放上去，要先经过 IFFT 还原后再显示。

滤波器标定

对于响应不规则的滤波器，我们用了二维查表来减小误差，但效果有限。更好的做法是在频域逐点校正：FFT 完成后，对每个 bin 乘以预先标定的校正系数，精度更高、延迟更低。

架构反思与优化方向

  • 信号链入口：AD9226 应配合差分驱动（如 AD8138），并在 ADC 前加一级窄带抗混叠滤波器，减少高频噪声和共模干扰对 ENOB 的影响。
  • SPI 通信瓶颈：FPGA 侧只传关心的频率 bin 和幅度，不传全谱；F4 侧用 DMA 接收避免 CPU 轮询。
  • 处理分工：高速运算留在 FPGA（采样、FFT、频域校正、峰值检测），F4 只负责控制逻辑、显示和通信，SPI 传输结构化结果而非原始数据，整体延迟会低很多。

收获

奈奎斯特与 FFT 的深入理解

在满足赛题 500 Hz 步频要求的前提下，FFT 点数选择非常关键。4095 点在较高频率下每个波形只有三个采样点，精度不足，需要扩大采样频谱或换成 8192 点（同样需要加宽频谱）。另外，单片机的 FFT 库通常只支持 4096 点，需要自己补充实现。

通信可靠性

SPI 通信中出现丢包、数据不完整等问题时，可以类比 TCP 的思路，封装一个自定义通信协议（带 CRC 校验）。FPGA 侧用 DMA 搬运数据，单片机侧用 DMA + 双 Buffer 缓冲区保证数据可靠。

今日学习

电容与电感

  • 电容充电时间常数：$\tau = RC$
  • 电感的本质：电流变化时产生磁场储能，会阻碍电流的进一步变化（楞次定律）

为什么需要保护电路

在大电流环境中，突然开启会导致启动电流（浪涌电流 / 冲击电流）瞬间过大，烧毁器件；突然关断则会因电感储能释放，产生激增电压电流，同样造成损坏。

一个写得好的 Skill 为什么好

最近看了一个我觉得很有意思的 Skill：grill-with-docs。它本体其实非常短，但设计思路很清楚：顶层 Skill 不自己堆很多规则，只负责把“持续追问方案”和“顺手沉淀文档”这两件事编排起来，再分别交给下游 Skill 去完成。真正的追问逻辑放在 grilling 里，术语表和 ADR 的整理放在 domain-modeling 里，连文档格式都继续拆到了单独模板文件中。

我觉得它写得好的地方主要有几点：

  • 顶层很薄，职责单一：入口只做编排，不把所有规则都塞进一个 SKILL.md，后续维护起来会轻很多。
  • description 写得准：一句话就把用途和触发场景说清楚，AI 更容易在合适的时候调用它。
  • 用组合代替重复造轮子：能复用已有 Skill 就复用，不重复写一套相似逻辑，这点和写代码时做模块拆分很像。
  • 流程和模板分离：执行规则放主 Skill，具体格式拆到单独文件，既节省上下文，也更方便后续修改。
  • 适合手动显式调用：像这种会不断追问、强行帮你把方案想透的 Skill，本来就更适合在需要的时候主动触发，而不是到处自动乱入。

这也让我更清楚地意识到：写 Skill 不是把 Prompt 变长，而是把“流程拆分、职责划分、触发条件、复用关系”都想明白。

区别总结：Prompt 适合固定的重复性任务（需要手动 /命令 触发），Skill 适合封装复杂的多步骤流程（自动触发）。当某个操作使用超过三次，就值得封装——需要手动控制时机用 Prompt，希望 AI 自动识别场景用 Skill。
